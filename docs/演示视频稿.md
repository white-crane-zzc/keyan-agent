# 科研小助手 Agent · 演示视频稿

> 用途：作者本人录屏 + 普通话配音的依据稿。目标时长 7 分 30 秒左右（要求 5–8 分钟），MP4 / 1080p 以上，可配中文字幕。

## 一、录制前准备

1. 启动服务：双击 `启动.cmd`，浏览器打开 `http://127.0.0.1:8000`，确认顶栏显示“模型已就绪 · deepseek-chat · 论文 28 篇”。
2. 确认库内为 28 篇论文、22673 块、2405 条参考文献；图谱页点一次“生成图谱”，确认基石为 BERT（被引 13）、28 节点 92 边。
3. 录屏软件设为 1920×1080 或更高、30 fps；只录浏览器窗口，不要录到桌面上的 `.env`、密钥、聊天窗口。
4. 提前备好素材：待上传的论文 v7 版本 PDF、示例 CSV（写作页可视化用）。
5. 语速按每分钟 180–200 字控制；每段口播之间留 1 秒空白，方便后期剪。
6. 字幕直接按下面“口播稿”原文生成，不要另写，避免与画面不一致。

## 三、口播稿（逐字，可直接照读）

### 0:00–0:35 片头 · 项目介绍

大家好，我是独立开发者 white-crane-zzc。这个作品叫科研小助手 Agent，是一个在本地运行的科研论文辅助系统。它解决的问题一句话就能说清：论文太多、英文太长、看完还记不住彼此之间的关系。系统把入库、阅读、问答、图谱、写作、追新这六件事串成一条流水线。接下来七分多钟，我先把六个页签走一遍，再讲 AI 技术上的取舍。

### 0:35–1:20 作品形态与运行规模

先说形态。它是一个跑在普通笔记本上的单进程 Web 应用：后端用 FastAPI，数据存单文件 SQLite，前端是原生页面，不依赖框架和构建工具，启动也不需要联外网。大模型走 OpenAI 兼容接口，默认接 DeepSeek，改一行配置就能指向本机 Ollama，完全离线也能跑。当前演示库是 28 篇论文、22673 个文本块、2405 条参考文献条目，引用图谱 28 个节点、92 条有向边，覆盖 Attention、BERT、GPT 这几条主线。

### 1:20–2:20 文库页：入库与判重

第一站，文库页。拖入 PDF 或者粘贴 arXiv 编号就能入库。这里演示判重：同一篇论文的 v1 和 v7，v7 首页多了一行授权声明，换行方式也不同。只比文本指纹，相似度只有 0.75，会漏判；系统改成标题、摘要前 320 字、首作者三个信号联合判断，实测判定为重复、相似度 0.954，并且把页数、字符数、参考文献条数的差异并列出来，跳过、并存还是替换，由使用者决定，系统不替你覆盖。

### 2:20–3:20 阅读页：版面、翻译与引用跳转

第二站，阅读页。左边是按页渲染的原始版面，双栏、公式、表格都保持原样，不改排；右边是按章节树整理出来的文本。点段落可以逐段翻译，也可以整页、整篇翻译；打开中英对照，两栏按滚动比例互相镜像。正文里的引用编号点一下，左栏对应参考文献会高亮，看完可以一键返回正文原来的位置。整篇能导出成 Markdown 或 HTML，章节顺序和参考文献都保留。

### 3:20–4:10 问答页：带出处的检索增强问答

第三站，问答页。勾选几篇论文再提问，不勾就是全库。答案下面每一条引用都带论文名、页码和章节，能直接回原文核对。这里问的是作者是谁，八位作者、八条引用都对得上。如果模型没配置、额度用尽或者网络断了，系统不报错，而是切到原文证据模式，返回带页码的命中片段——这也是我答辩敢断网的底气。

### 4:10–5:00 图谱页：引用网络与基石论文

第四站，图谱页。点一下生成全库引用网络，28 个节点、92 条边。右侧给出三类角色：基石论文、边缘论文、被引最多的外部工作。这次基石是 BERT，全库被引 13 次。PageRank 是矩阵幂迭代自己实现的，阻尼系数 0.85、迭代 60 次，没有引入科学计算库；判定条件直接写在接口返回里，方便核对。同一份引用上下文还能生成领域综述和未来工作建议。

### 5:00–6:20 写作页：框架、架构图与实验图表

第五站，写作页。输入一句研究想法，生成从摘要到结论的框架，参考文献只从勾选的清单里取，模型无权新增文献，这是防编造的关键。右边把 Mermaid 架构图在页面里直接渲染出来，也可以导出 TikZ 和 Graphviz 源码。下半部分上传实验数据，服务端出折线、柱状或者雷达图，自动配中英文图注和统计摘要。

### 6:20–6:45 推荐页：追踪新论文

第六站，推荐页。后台每 6 小时按文库主题抓一次 arXiv 最新论文，按摘要重合度排序，摘要里提到开源代码的加权优先，每条都给推荐理由；可以一键下载入库，也可以标记有用或不相关，反馈写回数据库，影响后面的排序。

### 6:45–7:30 AI 技术亮点：四个取舍

最后讲 AI 技术上的四个取舍。

第一，为什么用检索增强而不是微调。论文库一直在变，微调跟不上新论文；论文问答必须能指回原文，微调模型给不了出处；笔记本也没有训练和推理的算力。检索增强把事实交给解析和检索，把表达交给模型，两条职责都能单独验证。

第二，在提示层就把边界画死。先固定候选片段集合，模型只能在这个集合里作答；回答必须按“结论加引用编号”输出，编号和片段一一对应；写作框架的参考文献只允许取自勾选清单。

第三，检索是四层处理。约 45 组中英术语映射做查询扩展，模型把中文问题压成英文检索式，候选片段按语义重排取前 8 条，多路召回再按篇配额合并，避免长论文挤掉短论文；参考文献单独建块并降权，表格块豁免“数字占比过高”的降权，保证实验数据可检索。

第四，失败即降级。所有模型调用都有超时、重试和错误分类，任何一类失败都不抛给前端，而是回到原文证据模式；模型是可插拔的，换厂商只改配置。

### 7:30–7:45 收尾

实测口径也说明一下：9 道样例题里 6 道命中并给出正确页码，3 道没达标，原因写在技术文档第六章第四节，没有回避；干净环境复现是在本机新建的虚拟环境里完成的，没有再找第二台物理机器重复。代码、自测脚本和公开仓库都随作品提交。谢谢观看。

## 四、录制注意事项

1. 全程不要出现 `.env` 内容、DeepSeek 密钥、浏览器其他标签页；录屏前把无关窗口最小化。
2. 判重演示用的 v7 论文要预先准备好，避免现场下载等待。
3. 图表页出图约 1–2 秒，等待时不要静默，用口播覆盖。
4. 每段结束留 1 秒空白；字幕按口播稿原文，不要出现“AI 生成”水印。
5. 导出后核对：时长 5–8 分钟、分辨率 ≥1080p、MP4、音画同步、普通话清晰。
6. 上传平台用 B 站或抖音等公开平台，提交表单第 7 项只填以 https 开头的视频地址，**不要填网盘链接**。
