## 0. 需求分析

### 0.1 需求来源与场景

竞赛需求文档给出的场景是：本科生/研究生面对成百上千篇 PDF，读得慢、记不住、找不到、写不出。需求把它拆成 6 个功能域（1.1 内容解析与去重、1.2 对话与问答、1.3 翻译与阅读、1.4 自动下载与筛选、1.5 引用图谱与综述、1.6 写作辅助）和 3 个交付要求（可运行、可演示、可提交）。

### 0.2 我们对需求的理解与取舍

| 需求原文要点 | 我们的判定 | 落地方式 |
|---|---|---|
| 解析要"细粒度"，能定位到章节 | 必须做，且是全部功能的地基 | 自研结构解析器，标题层级由编号深度决定；参考文献、表格、图注、首页作者块各自成块 |
| 要做"内容去重" | 必须做，但阈值不能拍脑袋 | 标题相似度 + 摘要相似度 + 首作者三重信号，再叠加 MinHash 兜底 |
| 要"对话式问答"，不能瞎编 | 必须做，证据优先 | 检索命中块带论文名/页码/章节拼进上下文，回答强制带引用编号 |
| 要"翻译"，且要能对照读 | 必须做 | 划词翻译 + 整页/按页翻译 + 中英对照左右联动滚动 |
| 要"自动下载并筛掉为引用而引用" | 部分可自动化 | 参考文献结构化（含 arXiv id）→ 按正文引用次数给出"保留/存疑"判定 → 批量下载候选 |
| 要"引用图谱、综述、未来工作" | 必须做 | PageRank（自实现，去掉 scipy 依赖）+ 基石/边缘角色 + 综述/未来工作生成 |
| 要"写作辅助"（框架、架构图、数据图） | 必须做 | idea→框架、CSV→折线/柱状/雷达图（带图注与统计）、架构图支持 Mermaid/TikZ/Graphviz |
| 要"扫描件也能读" | 需求明确的测试项 | 集成离线 OCR（rapidocr-onnxruntime），无文本层的页自动走 OCR |
| 要"多用户协同、多智能体协同" | 需求列出但非核心 | 未实现，作为已知缺口在交付文档中明示，不假装做了 |
| 要"公网在线演示" | 需求列为提交要求 | 用户明确暂不做（项目零鉴权，公网开放等于任何人可删库），保留本地一键启动 |

### 0.3 关键约束

1. **不能联网也能跑**：解析、检索、图谱、翻译缓存全部本地；只有"生成"和"arXiv 抓取"需要网络，且可降级。
2. **数据不外发**：论文与解析结果只落本地 `data/`，模型调用只发命中的片段。
3. **失败要可见**：任何依赖缺失（模型未配置、OCR 未安装、scipy 缺失）都返回可用降级结果或明确错误，不静默失败。

## 1. 背景与目标

科研阅读的痛点集中在四件事：PDF 结构被压平、同一篇论文多版本难以甄别、读不懂的地方缺少上下文、读完难以沉淀成图谱与方法论。本项目的目标是把这四件事串成一条本地闭环流水线，且**在没有任何大模型凭证的环境下也能跑通**——模型是增强项，不是前置条件。

需求分解为六条主线：内容去重 → 细粒度解析 → RAG 问答与翻译 → 自动下载与推荐 → 引用图谱与综述 → 写作助手。全部落在单进程本地服务里，数据写盘不外发。

## 2. 总体架构

```
浏览器（六页签）
   │  REST / JSON / multipart
FastAPI (app/main.py)
   ├── pipeline.py   入库编排：解析 → 判重 → 落库 → 建索引
   │      ├── parser.py   PyMuPDF 结构解析
   │      └── db.py       SQLite（papers/chunks/refs/translations/recs）
   ├── search.py     BM25 检索（含中文二元组）+ 引用上下文拼装
   ├── llm.py        OpenAI 兼容调用（可插拔，缺省降级）
   ├── graph.py      networkx 引用图 + 自实现 PageRank
   └── arxiv.py      arXiv 下载/检索/推荐/反馈
data/  pdf/  index/  pages/{pid}/*.png  plots/  library.db
```

设计原则：

1. **解析一次、复用多次**。入库时把结构、段落块、参考文献、页码全部落库，问答/图谱/综述只读库，不重复解析 PDF（15 页论文首次解析约 10 秒，之后所有操作在百毫秒级）。
2. **模型无关**。`llm.py` 只认 `LLM_BASE_URL / LLM_API_KEY / LLM_MODEL`，任何 OpenAI 兼容端点（豆包、DeepSeek、通义、Kimi、OpenAI、本地 Ollama）都能直接换。`llm_ready()` 决定是否走生成路径，不 ready 时各接口返回可用的降级结果而不是报错。
3. **证据优先**。问答永远附带论文名 + 页码 + 章节的引用条目，前端可点击直接跳回原文页，从机制上压制幻觉。

## 3. 关键技术点与创新

### 3.1 结构解析：层级由编号深度决定，而非字号

PyMuPDF 给的是带 bbox 的文本块，不是逻辑结构。直接按字号判断标题在真实论文上会崩：arXiv 水印被当成标题、正文句子 "scholarly works." 被当成标题、"1\nIntroduction" 被拆成两块。

本项目的做法：

1. **合并编号块与标题块**：`_merge_number_headings` 把形如 `3.2` 的独立块与紧随其后的标题块合为一条。
2. **层级优先按编号深度**：`1` → L1，`1.1` → L2，`1.1.1` → L3；无编号时命中 `Abstract/Introduction/References` 等关键词给 L1；再退到字号与加粗。这条规则让 Attention 与 BERT 的 24/19 个章节层级全部正确。
3. **排除伪标题**：arXiv 戳、URL、邮箱、页面下半部、数字占比 >30% 或数字词 ≥5 的表格行，一律不判为标题（表格数据行不再污染「章节增删」对比）。
4. **标题自身不入树**：把组成标题的块（含被折行的第二行）按 `page+bbox` 加入跳过表，解决 BERT 标题第二行 "Language Understanding" 被误判为二级章节的问题。
5. **双栏识别**：统计文本块 x 中心的分布，以页面中线聚类判定栏数。BERT 识别为 2 栏，Attention 为 1 栏，与实际一致。
6. **参考文献双格式兜底**：先按 `[n]` 编号切分；条目少于 3 时退化为「作者块 + 年份块」合并，适配 ACL/NAACL 无编号格式（BERT 从 0 条恢复到 71 条）。

### 3.2 去重：单阈值 MinHash 不可用，改为三信号综合判定

实测同一篇 *Attention Is All You Need* 的 v1 与 v7，5-gram MinHash 相似度只有 **0.75**——v7 首页多了 Google 授权声明、排版换行不同，shingle 集合差异被放大。若按 0.90 单阈值判重，这对最典型的「同篇不同版本」会漏判。

改为综合判定：

```
标题相似度（SequenceMatcher，包含关系直接给 0.95）
摘要前 320 字相似度
首作者前两词是否命中
判重条件：(标题 ≥ 0.85 且 摘要 ≥ 0.45) 或 (标题 ≥ 0.95 且 作者命中) 或 MinHash ≥ 阈值
```

实测相似度 **0.954**，并输出差异与建议：

| 项 | 库内 v7 | 新上传 v1 |
|---|---|---|
| 页数 | 15 | 15 |
| 字符数 | 27748 | 26074 |
| 参考文献 | 40 | 36 |
| 图 / 表 | 2 / 4 | 1 / 4 |

版本新旧由页面/字符规模与修改时间共同推断，给出「库里版本更新，建议保留库里版本」。用户仍可选择 `keep_both` 并存或覆盖。

### 3.3 检索：BM25 + 中文二元组 + 结构降权

- 分词：英文按词、中文按二元组（不引入 jieba 这类重依赖，竞赛环境零安装成本）。
- 打分：标准 BM25（k1=1.5, b=0.75）。
- **结构降权**：命中块若以 `Figure/Table/图/表` 开头或数字占比 >35%，分数 ×0.55。这条规则直接消除了「问多头注意力，答 Figure 1 图注」这类噪声。

### 3.4 引用图谱：PageRank 与角色划分

- 只用参考文献标题做匹配（`_title_match`：词面 Jaccard ≥0.6，短标题放宽为包含关系），不依赖外部元数据，离线可用。
- PageRank 自实现（`numpy` 幂迭代 60 次，悬挂节点均分），**避免引入 scipy**——`nx.pagerank` 在缺 scipy 时会直接抛 `ModuleNotFoundError`，这正是本项目早期 `/api/graph` 500 的原因。
- 角色：被引数等于全图最大且 >0 → **基石**；入度 0 且有出度 → **边缘**；其余 **中间**。
- 同时统计「被引最多的外部工作」Top10，用于判断本文在学术脉络中的位置。

### 3.5 可插拔模型与降级路径

| 能力 | 无模型时 | 有模型时 |
|---|---|---|
| 问答 | 返回带页码的原文证据（可直接比对） | 基于证据生成答案 + citations |
| 翻译 | `degraded: true` + 说明 | 逐块翻译，代码/公式块跳过，结果缓存入库 |
| 综述/未来工作 | 输出结论段/未来工作段原文 | 归纳成综述，禁止提出已被最新论文完成的点 |
| 论文框架 | 输出库内真实文献清单 | 生成含章节结构的框架，References 只允许引用库内文献 |
| 架构图 | 固定 mermaid 示例 | 按描述生成 mermaid / tikz / graphviz |

降级不是「返回错误」，而是「返回可用的最小结果」，保证演示链路在任何机器上都不中断。

### 3.6 CSV → 学术图：图注、统计与趋势结论

`/api/plot` 读取 CSV，按 `kind`（line/bar/radar）出图，同时产出：中文图注（含数据规模）、统计摘要（行数、列名、均值/最大值）、趋势结论模板。图注与统计与图同源生成，避免「图是图的、注是注的」脱节。

## 4. 数据模型

```sql
papers(id, sha, title, authors, year, abstract, filename, n_pages, n_chars, columns,
       n_refs, minhash, meta_json, struct_path, created_at)
chunks(id, paper_id, page, section, text, ord)
refs(id, paper_id, ord, raw, title, authors, year, arxiv_id)
translations(paper_id, chunk_id, target, source, text)
recs(arxiv_id, title, verdict, ts)
```

`struct_path` 指向 `data/index/{pid}.json`，保存完整结构（outline/tables/figures/blocks），页面渲染图另存 `data/pages/{pid}/{n}.png`。删除论文时三处同时清理。

## 5. 接口与前端

REST 共 18 个端点（见 README 表）。前端为无构建依赖的原生三件套，六个页签对应六条需求主线；阅读页用 SVG 透明层覆盖在页面渲染图上做精确选词，划词后右侧浮出译文；对照模式按文本块序号做滚动联动。

## 8. 限制与后续

1. **公式**：以 PDF 渲染图呈现，未抽取 LaTeX 语义。
2. **数值型召回**：表格已入块，但问表格里的单个数字（如被超越模型的 26.36 BLEU、GPT-1 的 117M）仍可能召回不到，下一步引入本地嵌入模型做向量检索。
3. **OCR 速度**：CPU 单页约 12s，整本扫描书走 OCR 需数小时；有文本层的页仍走原生解析。
4. **引用价值判定**：按"正文 [n] 出现次数"给出保留/存疑，属启发式，不替代人工判断。
5. **541 页官方书籍**：官方 PDF 下载链路被网络重置，未获得原文件；已用 540 页同规模文档完成压测。
6. **多用户协同、多智能体协同**：未实现。
7. **公网演示**：项目零鉴权，公网开放前必须先加访问控制；当前只提供本地一键启动。

## 9. 技术创新点与应用创新点

### 9.1 技术创新点

1. **结构解析以"编号深度"定层级，而不是字号**。`1 → L1`、`1.1 → L2`、`1.1.1 → L3`，配合 `_merge_number_headings` 先把被拆开的编号块与标题块合并，再按"数字占比 > 30% 或数字词 ≥ 5"排除把数据行误判为标题。这条规则让双栏 BERT 从"9 页正文"恢复到 16 页全文。
2. **三信号判重替代单阈值 MinHash**。同篇论文 v1/v7 的 MinHash 只有 0.75，单阈值 0.90 直接漏判；改为「标题相似度 + 摘要前 320 字 + 首作者前两词」三信号组合（标题≥0.85 且摘要≥0.45，或标题≥0.95 且作者命中），实测 v1/v7 = 0.954，并输出差异清单供人决定保留哪版。
3. **去 scipy 的自实现 PageRank**。`nx.pagerank` 内部依赖 scipy，缺包时整图 500；改为 numpy 幂迭代（60 轮、alpha=0.85、悬挂节点均分），零额外依赖，27 节点 92 边一次生成约 4s。
4. **"参考文献之后是附录"的截断修复**。原逻辑把参考文献起点之后的所有页都当参考文献丢弃，导致 BERT 16 页只入库 9 页。修复判据是：参考文献区内出现"字号明显大于正文的短行"即视为附录标题，refs_end 截到该处，其后继续按正文入库。
5. **跨语言检索四层链路**。中文问英文论文，词面对不上；用「术语表 TERM_MAP + expand_query → 模型压英文检索式 → 模型按语义重排 top30→top8 → 多路合并 + 按篇配额」四层把"多头注意力每头维度"落到 3.2.2。
6. **无文本层页面自动 OCR**。`sum(text) < 40` 触发离线 OCR（rapidocr-onnxruntime），OCR 的像素框按 `72/dpi` 换算回 PDF 点坐标，与原生文本块共用同一套后续解析逻辑。
7. **引用双向跳转**。正文 `[13]` → 参考文献第 13 条高亮 → 一键返回原页原位置；中英对照模式下左右两栏按滚动比例联动，并由开关自动补齐当前页译文。

### 9.2 应用创新点

1. **"证据模式"是默认态而非兜底态**。没有模型凭证时，问答直接返回带论文名/页码/章节的原文片段，而不是报"未配置模型"，评审现场无需 key 也能演示。
2. **一份 PDF 只解析一次**。入库即固化结构、块、参考文献、页码；问答/图谱/综述/翻译全部读库，15 页论文首次 10s，之后百毫秒级。
3. **模型可插拔、可换供应商**。只认三个环境变量，豆包/DeepSeek/Kimi/通义/OpenAI/本地 Ollama 直接换，`.env` 内置六组注释模板。
4. **判重结果给人看差异，而不是替人做决定**。重复上传时弹出"标题/年份/页数/参考文献数/摘要首句"逐项对比，并给 `keep_both / replace / cancel` 三个选项。
5. **一次阅读动作串起四个产物**：读一页 → 划词翻译 → 点引用跳文献 → 导出 Markdown/HTML，读的过程直接沉淀成可交付材料。
6. **引用价值筛查**。按"正文引用次数"自动标出仅引用 1 次或未被引用的条目，把"为引用而引用"从人工排查变成一眼可见。

## 10. 总结与展望

本项目把"读论文"拆成一条可验证的本地流水线：解析 → 判重 → 检索 → 问答/翻译 → 图谱 → 写作，六步全部落在一个 FastAPI 进程和一份 SQLite 里，无外部服务依赖。当前交付物包含 27 篇真实论文的完整文库（22217 块 / 2369 条参考文献）、可双击启动的本地 Web 应用、需求 9 道样例题的实测记录，以及 12 项缺口清单。

已经验证的能力：结构解析（单/双栏、附录截断、表格入块、首页作者块）、三信号判重、跨语言检索、证据化问答、引用双向跳转、中英对照联动、PageRank 图谱、Markdown/HTML 重排导出、引用价值筛查、CSV 学术绘图、扫描件 OCR。

明确的不足：表格内单个数字的召回（第 4/7 题）、541 页长书未实测、多用户与多智能体协同未实现、公网演示因鉴权缺失暂缓。

下一步优先级：
1. 引入本地嵌入模型（约 100MB）做向量检索，补数值型召回；
2. 长文档分页 OCR + 断点续跑，把 541 页长书纳入测试；
3. 加最小鉴权（口令 + 只读演示账号）后再考虑公网演示；
4. 定时任务定期抓 arXiv 新论文并按图谱邻近度推送。
