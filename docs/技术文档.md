# 科研小助手 Agent 技术文档

版本 1.0 ｜ 2026-11 ｜ 本地 Web 应用（FastAPI + 原生前端 + SQLite）

---

## 1. 背景与目标

科研阅读的痛点集中在四件事：PDF 结构被压平、同一篇论文多版本难以甄别、读不懂的地方缺少上下文、读完难以沉淀成图谱与方法论。本项目的目标是把这四件事串成一条本地闭环流水线，且**在没有任何大模型凭证的环境下也能跑通**——模型是增强项，不是前置条件。

需求分解为六条主线：内容去重 → 细粒度解析 → RAG 问答与翻译 → 自动下载与推荐 → 引用图谱与综述 → 写作助手。全部落在单进程本地服务里，数据写盘不外发。

---

## 2. 总体架构

```
浏览器（六页签）
   │  REST / JSON / multipart
FastAPI (app/main.py)
   ├── pipeline.py   入库编排：解析 → 判重 → 落库 → 建索引
   │      ├── parser.py   PyMuPDF 结构解析
   │      └── db.py       SQLite（papers/chunks/refs/translations/recs）
   ├── search.py     BM25 检索（含中文二元组）+ 引用上下文拼装
   ├── llm.py        OpenAI 兼容调用（可插拔，缺省降级）
   ├── graph.py      networkx 引用图 + 自实现 PageRank
   └── arxiv.py      arXiv 下载/检索/推荐/反馈
data/  pdf/  index/  pages/{pid}/*.png  plots/  library.db
```

设计原则：

1. **解析一次、复用多次**。入库时把结构、段落块、参考文献、页码全部落库，问答/图谱/综述只读库，不重复解析 PDF（15 页论文首次解析约 10 秒，之后所有操作在百毫秒级）。
2. **模型无关**。`llm.py` 只认 `LLM_BASE_URL / LLM_API_KEY / LLM_MODEL`，任何 OpenAI 兼容端点（豆包、DeepSeek、通义、Kimi、OpenAI、本地 Ollama）都能直接换。`llm_ready()` 决定是否走生成路径，不 ready 时各接口返回可用的降级结果而不是报错。
3. **证据优先**。问答永远附带论文名 + 页码 + 章节的引用条目，前端可点击直接跳回原文页，从机制上压制幻觉。

## 3. 关键技术点与创新

### 3.1 结构解析：层级由编号深度决定，而非字号

PyMuPDF 给的是带 bbox 的文本块，不是逻辑结构。直接按字号判断标题在真实论文上会崩：arXiv 水印被当成标题、正文句子 "scholarly works." 被当成标题、"1\nIntroduction" 被拆成两块。

本项目的做法：

1. **合并编号块与标题块**：`_merge_number_headings` 把形如 `3.2` 的独立块与紧随其后的标题块合为一条。
2. **层级优先按编号深度**：`1` → L1，`1.1` → L2，`1.1.1` → L3；无编号时命中 `Abstract/Introduction/References` 等关键词给 L1；再退到字号与加粗。这条规则让 Attention 与 BERT 的 24/19 个章节层级全部正确。
3. **排除伪标题**：arXiv 戳、URL、邮箱、页面下半部、数字占比 >30% 或数字词 ≥5 的表格行，一律不判为标题（表格数据行不再污染「章节增删」对比）。
4. **标题自身不入树**：把组成标题的块（含被折行的第二行）按 `page+bbox` 加入跳过表，解决 BERT 标题第二行 "Language Understanding" 被误判为二级章节的问题。
5. **双栏识别**：统计文本块 x 中心的分布，以页面中线聚类判定栏数。BERT 识别为 2 栏，Attention 为 1 栏，与实际一致。
6. **参考文献双格式兜底**：先按 `[n]` 编号切分；条目少于 3 时退化为「作者块 + 年份块」合并，适配 ACL/NAACL 无编号格式（BERT 从 0 条恢复到 71 条）。

### 3.2 去重：单阈值 MinHash 不可用，改为三信号综合判定

实测同一篇 *Attention Is All You Need* 的 v1 与 v7，5-gram MinHash 相似度只有 **0.75**——v7 首页多了 Google 授权声明、排版换行不同，shingle 集合差异被放大。若按 0.90 单阈值判重，这对最典型的「同篇不同版本」会漏判。

改为综合判定：

```
标题相似度（SequenceMatcher，包含关系直接给 0.95）
摘要前 320 字相似度
首作者前两词是否命中
判重条件：(标题 ≥ 0.85 且 摘要 ≥ 0.45) 或 (标题 ≥ 0.95 且 作者命中) 或 MinHash ≥ 阈值
```

实测相似度 **0.954**，并输出差异与建议：

| 项 | 库内 v7 | 新上传 v1 |
|---|---|---|
| 页数 | 15 | 15 |
| 字符数 | 27748 | 26074 |
| 参考文献 | 40 | 36 |
| 图 / 表 | 2 / 4 | 1 / 4 |

版本新旧由页面/字符规模与修改时间共同推断，给出「库里版本更新，建议保留库里版本」。用户仍可选择 `keep_both` 并存或覆盖。

### 3.3 检索：BM25 + 中文二元组 + 结构降权

- 分词：英文按词、中文按二元组（不引入 jieba 这类重依赖，竞赛环境零安装成本）。
- 打分：标准 BM25（k1=1.5, b=0.75）。
- **结构降权**：命中块若以 `Figure/Table/图/表` 开头或数字占比 >35%，分数 ×0.55。这条规则直接消除了「问多头注意力，答 Figure 1 图注」这类噪声。

### 3.4 引用图谱：PageRank 与角色划分

- 只用参考文献标题做匹配（`_title_match`：词面 Jaccard ≥0.6，短标题放宽为包含关系），不依赖外部元数据，离线可用。
- PageRank 自实现（`numpy` 幂迭代 60 次，悬挂节点均分），**避免引入 scipy**——`nx.pagerank` 在缺 scipy 时会直接抛 `ModuleNotFoundError`，这正是本项目早期 `/api/graph` 500 的原因。
- 角色：被引数等于全图最大且 >0 → **基石**；入度 0 且有出度 → **边缘**；其余 **中间**。
- 同时统计「被引最多的外部工作」Top10，用于判断本文在学术脉络中的位置。

### 3.5 可插拔模型与降级路径

| 能力 | 无模型时 | 有模型时 |
|---|---|---|
| 问答 | 返回带页码的原文证据（可直接比对） | 基于证据生成答案 + citations |
| 翻译 | `degraded: true` + 说明 | 逐块翻译，代码/公式块跳过，结果缓存入库 |
| 综述/未来工作 | 输出结论段/未来工作段原文 | 归纳成综述，禁止提出已被最新论文完成的点 |
| 论文框架 | 输出库内真实文献清单 | 生成含章节结构的框架，References 只允许引用库内文献 |
| 架构图 | 固定 mermaid 示例 | 按描述生成 mermaid / tikz / graphviz |

降级不是「返回错误」，而是「返回可用的最小结果」，保证演示链路在任何机器上都不中断。

### 3.6 CSV → 学术图：图注、统计与趋势结论

`/api/plot` 读取 CSV，按 `kind`（line/bar/radar）出图，同时产出：中文图注（含数据规模）、统计摘要（行数、列名、均值/最大值）、趋势结论模板。图注与统计与图同源生成，避免「图是图的、注是注的」脱节。

## 4. 数据模型

```sql
papers(id, sha, title, authors, year, abstract, filename, n_pages, n_chars, columns,
       n_refs, minhash, meta_json, struct_path, created_at)
chunks(id, paper_id, page, section, text, ord)
refs(id, paper_id, ord, raw, title, authors, year, arxiv_id)
translations(paper_id, chunk_id, target, source, text)
recs(arxiv_id, title, verdict, ts)
```

`struct_path` 指向 `data/index/{pid}.json`，保存完整结构（outline/tables/figures/blocks），页面渲染图另存 `data/pages/{pid}/{n}.png`。删除论文时三处同时清理。

## 5. 接口与前端

REST 共 18 个端点（见 README 表）。前端为无构建依赖的原生三件套，六个页签对应六条需求主线；阅读页用 SVG 透明层覆盖在页面渲染图上做精确选词，划词后右侧浮出译文；对照模式按文本块序号做滚动联动。

浏览器真机验收采用 CDP 驱动无头 Edge（`tests/ui_flow.py`）：真实点击页签、输入问题、点「提问/生成图谱/生成框架/获取推荐」，断言输出并截图，同时收集 `Runtime.exceptionThrown`。当前六页签全绿，无 JS 异常。

## 7. 工程质量

- 两套自动化脚本：`tests/e2e_test.py`（接口级 10 步）、`tests/ui_flow.py`（浏览器交互级）。
- 服务日志分离 `data/server.out.log` / `server.err.log`，异常栈可追溯。
- 所有写操作幂等：重复上传按判重逻辑拦下，翻译结果哈希缓存，索引按 chunk 数变化自动重建。
- 敏感信息全部走 `.env`，`.gitignore` 排除 `data/`、`.venv/`、`.env`。

## 8. 限制与后续

1. **扫描件**：仅取文本层，无 OCR 时解析为空，需接 PaddleOCR/Tesseract。
2. **公式**：以 PDF 渲染图呈现，未抽取 LaTeX 语义。
3. **参考文献匹配**：无编号或中文格式的条目匹配率低于英文标准格式，可引入「作者+年份」或 arXiv id 兜底。
4. **大模型**：当前环境无凭证，生成类能力待用户填入 key 后验证。
5. **在线演示**：本地环境无公网入口，需部署到有公网 IP 的机器或内网穿透后再提供演示地址。
